## Must-fix

M1. Wage calibration feeds back on itself and oscillates. hr.py:213-216 stores `ratio = actual / wage`, where `wage` is the already calibrated wage. hr.py:363-369 then multiplies the *band* by the p80 of those ratios. Once calibrated wages enter the 30-ratio window, the ratios fall toward 1.0 and the wage drops back to the band.
Repro (exp1): true use is a constant 90,000 on band M. The wage sequence, sampled every 4th hire: 60000, 60000, 90000, 90000, 90000, 90000, 90000, 90000, **60000**, 90000, ..., **60000, 60000**, 90000. The helper is underpaid by a third, periodically, for ever.
Fix: store `actual / band` (record the band, or `wage_tokens / factor`, in the contract), or apply the quantile to `actual` directly. Confidence: high.

M2. The pass record can move without the script's check (this breaks I-17). hr.py:559-566 trusts any boolean `passed` already present in the contract JSON, and runs `contract["check"]` straight from that file. The contract sits in `<project>/.brain/log/hr/`, which a builder helper can write to.
Repro (exp2): hire with check "false", set `"passed": true` in the contract, then settle -> passed True and no check_exit. A second variant: rewrite `"check": "true"` -> passed True.
Fix: keep the check and the result outside the helper's reach (a hash of the check in the hire record, or an `hr` store in the brain), and run the check unless `check_exit` was produced by this script. Confidence: high on the mechanism. That a real helper would do this is unconfirmed.

## Should-fix

S1. The four-helper cap is unenforced or wrong.
(a) hr.py:643 only applies the cap when `project is not None`. A CLI repro with TMPDIR in scratch and no project made 6 hires and wrote 6 open contracts. /tmp/brain-hr already holds 30 open contracts from this session.
(b) open_contracts (hr.py:602-604) counts every session's contracts, while settle_open (hr.py:591) settles only the current session's. Repro: 4 contracts from "crashed-session", then a new session runs close -> `''`, and open_contracts -> 4 >= max_helpers. Every later hire answers "do not hire yet" unless `--force` is used.
(c) The "closest -> hire again with --template" flow (hr.py:516, 660) leaves the first plain contract open as an orphan.
Fix: count the cap per session (or per project) in every mode, and have close or settle sweep stale contracts.

S2. An "unmatched" contract is never retried, and the CLI message is false. hr.py:570 writes status "unmatched". open_contracts only lists "open" contracts, yet cmd_settle (hr.py:696) prints "left open". Repro exp2 C: after an early settle, the contract is no longer in open_contracts. A settle run before the helper's transcript reaches disk loses that hire permanently.

S3. Contract ids collide. hr.py:500 hashes `now_iso|task|session` at one-second resolution. Repro exp2 D: 3 identical hires in the same second all got `h-20261110-8cc4a3`, so later contracts and briefs overwrite earlier ones. Parallel shards with the same goal and different `--owns` hit this. Fix: add a counter or random salt.

S4. Constraints are silently dropped. hr.py:413-418 takes `method[:4] + drift + extras`, then cuts the list at `[:6]`. All 100 templates have 4 method lines and a drift, so only the first `--also` survives. Repro exp1: extras kept ['EXTRA-ONE'] out of 3. A fifth method line, which the schema allows (schema:13), would also be dropped. Fix: never drop lead-supplied lines, and warn if the brief goes over its limit.

S5. The brief-length promise does not hold. GUIDELINES:39 says the 230-word stable body keeps "a rendered brief ... within 350". Repro exp1: with a 60-word task and a 25-word why, 99 of 100 templates go over 350. This review's own contract carries the lint error "brief is 381 words (limit 350)", and the brief was still delegated (cmd_hire returns 1 but writes the brief anyway).
Research 01 line 230 sets the stable body at 160 words, and line 9 puts the stable parts in the agent file rather than the brief. The rack deviates from its source here without saying so.

S6. With no check, done_when points at a check that does not exist. hr.py:419-420 renders "the check named in the task". Evidence: /tmp/brain-hr/h-20261110-cd75fa.md:18, and in exp1 "<done_when>the check named in the task exits 0 on a clean clone...". Fix: render the template's inspection without a command, or refuse.

S7. A hire with no project and no `--workdir` never runs its check. hr.py:503 sets workdir "" and hr.py:560 sets where=None, so passed stays None. 28 of the 31 contracts in /tmp/brain-hr have a check and no workdir. Fix: default the workdir to the cwd.

S8. One malformed template breaks every hire. load_rack (hr.py:85) does not validate. Repro exp2 E: a template without an id -> hire KeyError 'id' (hr.py:321); when null -> TypeError at hr.py:295; integer keywords -> TypeError, and audit does not flag them at all (schema:11 has no item type). Fix: skip invalid templates in load_rack, and type-check list items.

S9. Read-only work is given write tools. Research 02-archetypes assigns scout to repo-cartographer (line 49), history-digger (line 55) and others. The rack has 0 scout templates. repo-cartographer, history-digger, token-cost-auditor, api-live-prober and statistical-tester run on builder (Edit/Write/Bash), and their only fence is a scope_rule sentence ("Read-only on the repository ... edit and commit nothing", discovery.jsonl:1). 13 base agents differ from the research table, with no recorded reason.
