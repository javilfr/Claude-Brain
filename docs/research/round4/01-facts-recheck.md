## Q1. Does changing effort mid-session invalidate the cache in Claude Code?

Answer (high confidence): it depends on model and provider. With an API key or a Claude subscription on Fable 5.1 and later, Opus 5.5, Sonnet 5.5 and Haiku 5.5, no. Elsewhere, yes.
- "On most models, changing the effort level mid-session means the next request reads the entire conversation history with no cache hits." "With an API key or a Claude subscription, changing effort keeps the cache on Fable 5.1 and later, Opus 5.5, Sonnet 5.5, and Haiku 5.5." Exceptions where it behaves "as on most models": Amazon Bedrock, Google Cloud's Agent Platform, a Claude apps gateway, `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS`, or a HIPAA configuration. Before v2.1.260 changing effort on Fable 5.1 also invalidated it. https://code.claude.com/docs/en/prompt-caching.md [sourced]
- Contrary (raw API, not Claude Code): "Changing the top-level `effort` value between requests invalidates the prompt cache. ... use a per-message effort change (beta) instead, which keeps the cache." https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5.md ; the Fable 5.2 guide says the same ("Where per-message effort isn't available, set a new top-level `effort` value on the next request, which starts the cache over"). https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2.md [sourced]
- model-config.md has no cache statement about effort (only that the new level applies from the next message). https://code.claude.com/docs/en/model-config.md [sourced]
- Implication [estimate]: the brain's model-and-effort routing inside Claude Code on the Anthropic API can change effort mid-session without a cache penalty; changing model still costs a cold turn.

## Q2. Documented limit for total skill description length at session start?

Answer (high confidence): yes. Quote: "The budget scales at 1% of the model's context window. When the listing overflows, Claude Code drops descriptions starting with the skills you invoke least, so the skills you use most keep their full text." "The listing always contains every skill name, but if you have many skills, Claude Code drops some descriptions to fit the listing's character budget." https://code.claude.com/docs/en/skills.md [sourced]
- Raise it with `skillListingBudgetFraction` (example `0.02` = 2%) or `SLASH_COMMAND_TOOL_CHAR_BUDGET` (fixed character count). Per-entry cap: "each entry's combined text is capped at 1,536 characters regardless of budget ... configurable with `skillListingMaxDescChars`". `"name-only"` in `skillOverrides` lists a skill without a description. Overflow writes a warning to the debug log (`--debug`). `/doctor` estimates the listing cost; `/skill-doctor` (v2.1.252+) shows per-skill cost. [sourced]
- Unknown: the unit of the 1% (characters vs tokens) and the resulting byte count on a 1M window are not stated. The earlier memo's "15,000 chars at Claude Code 2.0.70" figure is not on today's page and should not be used. [unconfirmed]

The page lists Fable 5.2 and Opus 5.5 among the models it covers. https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices.md [sourced]
