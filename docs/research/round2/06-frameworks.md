# 06 - Community orchestration frameworks: what to take, what to reject (competitive analyst view)

Date: 2026-11-10. Confidence: medium-high on the verdicts, low-medium on any quantitative cost claim, because almost no framework publishes a neutral token measurement. Tags: [F] = fact read from the cited source; [E] = my estimate or inference; [unverified] = secondary or unconfirmed.

## 0. Bottom line

1. Popularity is not evidence here. Star counts are huge (spec-kit 149.1k, Superpowers 315.3k, OpenSpec 74.5k, BMAD 55.2k, Ruflo about 77-81k; all [F] from the repo pages below) but I found no independent controlled benchmark for any of them. The best independent evidence is two academic papers that cut AGAINST the common framework pattern (big always-loaded context files, self-written skills).
2. Take: deterministic scripts instead of LLM calls (ccpm), fresh context per task plus on-disk state plus test "backpressure" (Ralph, GSD), on-demand skills with small descriptions, tool-surface tiering (Task Master), diagnostics over skill misfires (Superpowers), delta-style spec changes with archive (OpenSpec), keyword/trigger-scoped loading (OpenHands).
3. Reject: multi-phase document ceremony for ordinary tasks (spec-kit/Kiro/BMAD full path), same-session Ralph stop-hook loops, swarm/hive-mind orchestration layers, large always-on MCP tool surfaces, unsourced "30-50% token savings" modes, any self-written skill promoted without a verifier.
4. Three gaps in our design (section 5): (a) no verifier-gated promotion/ablation of self-generated knowledge; (b) no skill-trigger telemetry and description budget; (c) no compaction-proof handoff and per-task iteration contract with deterministic backpressure.

## 2. Independent evidence that should drive decisions

- AGENTS.md study (ETH Zurich/LogicStar, arXiv 2602.11988, ICLR 2026): context files "do not generally improve task success rates" and raise cost "by over 20% on average"; agents follow the instructions, repo overviews were not helpful; LLM-generated files helped only when other docs were removed. Authors suggest minimal, human-written requirements only. [F] https://arxiv.org/abs/2602.11988 . Specific effect sizes (-0.5 to -2% LLM-generated, ~+4% human-written) are from a secondary summary [unverified] https://www.themoonlight.io/review/evaluating-agentsmd-are-repository-level-context-files-helpful-for-coding-agents . Caveat: tested SWE-bench Lite and one new benchmark with Claude Code (Sonnet 4.5), Codex and Qwen Code, i.e., older models than ours.
- SkillsBench (arXiv 2602.12670): curated skills raised average pass rate 33.9% -> 50.5% (+16.6 pp) over 87 tasks / 18 configs; focused skill sets of at most three modules beat larger bundles; a smaller model with skills can match a larger one without. [F abstract] https://arxiv.org/abs/2602.12670 . Secondary summaries of an earlier version: software engineering gained only +4.5 pp (versus +51.9 healthcare), 16 of 84 tasks regressed, and SELF-GENERATED skills averaged about -1.3 pp [secondary, version numbers differ] https://arxiv.org/html/2602.12670v1 .
- Fowler/Böckeler on SDD tools: generated spec files were heavier to review than the code; none of the three reviewed suited most real tasks. [F] https://www.martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html (Oct 2025; tool versions have moved on, so the details may be stale).

[E] Inference: the pattern "write lots of prose for the agent" has weak independent support; "give a small, curated, verified procedure only when needed" has the only positive controlled result.

## 4. REJECT (with evidence)

| Mechanism | Why | Evidence |
|---|---|---|
| Full multi-phase spec pipeline for every task (spec-kit specify/plan/tasks, Kiro 3-file, BMAD persona chain) | Review cost exceeds code review; duplicates existing code; overkill below ~5 points; our sizing tiers 0-3 already route small work around it | Fowler [F]; OpenSpec's own jab at spec-kit [competitor claim] |
| Constitution / long principles file loaded always | Agent over-applies articles; ETH shows context files raise cost >20% without success gain | Fowler [F]; arXiv 2602.11988 [F] |
| Same-session Ralph stop-hook loop | Context accumulates, errors carry forward, hangs, silent stop; hooks do not load in our session type anyway | Wojcik [F, anecdotal]; brief platform facts |
| Swarm / hive-mind / consensus layers (Ruflo) | Project's own audit admits fabricated benchmarks and no-op hooks; "hive-mind" is a spawned Claude; our measured multi-agent cost is about 15x [brief] | andrew.ooo review [F, secondary]; anonymous gist [unverified] |
| Large MCP tool surfaces always on | 5k-21k tokens (Task Master measured), 314 tools (Ruflo) vs our ~1.25k [E] total; and repo .mcp.json does not load here | Task Master README [F] |
| Unsourced "30-50% fewer tokens" modes (SuperClaude Token-Efficiency, MCP bundle) | No baseline or method published; our measured cost is 57% output, so compressing input prompts attacks the minority share | SuperClaude README [F]; brief cost profile |
| Self-written skills/playbooks auto-promoted on model judgement | Self-generated skills averaged about -1.3 pp; software engineering gain even for curated skills only +4.5 pp | SkillsBench summaries [secondary, version-dependent] |
| Adopting persona agents as a taxonomy (PM/architect/UX...) | No evidence personas add value beyond context isolation; our 6 agents are role-by-cost, which is what routing statistics can actually tune [E] | No controlled evidence found [absence] |

## 5. Three "we are missing this" gaps

1. Verifier-gated promotion and ablation of self-generated knowledge. Our pipeline promotes memory/playbook deltas with evidence and helpful/harmful counters, but counters are self-reported by the same model that wrote the item. SkillsBench suggests unverified self-written procedures are neutral-to-harmful, and ETH shows extra context costs >20%. Fix: promotion requires (a) a replay or held-out task where the item changed a deterministic outcome (tests/gates) or tokens, (b) `brain ablate` showing no regression, and (c) a per-item "tokens loaded vs times it changed an outcome" ratio that drives decay. Hardcode a maximum of 3 loaded procedures per task.
2. Skill-trigger telemetry and a context budget lint. We have ten skills and six agents whose descriptions all ride in every turn (measured ~270-340 tokens per description in one user's setup [F weak], so ten skills could be ~3,000 tokens [E], more than twice the CLAUDE.md). Nothing in our design measures whether skills fire, misfire, or fall off the list (silent drop past a character budget, per Superpowers' author). Fix: A2 + A4 above, and record skill invocations in the token ledger by task class.
3. Compaction-proof handoff and per-task acceptance contract. Superpowers admits its bootstrap is lost after compaction on some harnesses; Ralph/GSD/ccpm all survive because state is on disk and each unit has a mechanical pass/fail. We have `brain boot` and a ledger, but no defined resume packet and no rule that every delegated task carries an acceptance command. Fix: `brain resume` (<=15 lines: current task id, last green gate, open requirements, next action) referenced in one line of CLAUDE.md so it can be re-run after compaction; `brain task` refuses to dispatch a sub-agent without an acceptance command or an explicit "review-only" flag.

## 6. Unknowns and caveats

- No neutral token measurement exists for Superpowers, SuperClaude, BMAD, spec-kit, GSD, Ruflo (current). Any "X saves N%" is vendor or single-blogger.
- Many sources are blog or aggregator pages; the search tool returned few direct Reddit/Threads/X threads. Anonymous Ruflo audit claims are unverified; only the project's own acknowledged issues (via one review) are treated as facts-with-caveat.
- GitHub star counts are as shown on pages fetched today and some pages (Ruflo review) are internally inconsistent.
- ETH and SkillsBench used 2025-era models; transfer to Fable 5.2 / Opus 5.5 is plausible [E] but unmeasured, which is why A8 exists.
- Cursor/Windsurf rules, aider primary docs, and OpenHands internals were not studied in depth.
- Skill description budget (15,000 chars at Claude Code 2.0.70) may have changed since December 2025; verify in the live session before hardcoding [unverified for today].
